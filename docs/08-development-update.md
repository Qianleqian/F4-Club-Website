# 后续规划实现与验证记录

日期：2026-11-17。本文记录本地开发版增量；服务器部署需单独进行。

## 四角色功能

- 管理员：创建账号、启用禁用、角色分类、按账号或姓名搜索、查看全部活动、报名名单和负责人名单。社团负责人显示在学生类别中。
- 教师：审核活动和新社团申请，填写驳回意见，查看负责人名单及已通过活动，设置结束时间。活动页面区分审核状态和未开始、进行中、已结束；没有结束时间时不猜测状态。
- 参加活动的学生：关键词、日期和兴趣分类筛选、报名确认、已报名列表、活动变更提示、站内消息和修改记录。公开活动可分享链接、生成二维码和下载海报；学生可对已报名活动设置提前 1 小时、1 天或 7 天的站内提醒。
- 社团负责人：使用固定表单提交活动、新社团申请和新闻公告，查看审核意见与状态、编辑并重新提交、查看报名名单和剩余名额。每个账号当前仅关联一个社团；新社团申请获批时转入新社团，若旧社团有活动且没有其他启用的负责人，系统拒绝转移，需管理员先安排负责人。

## 行为约定

活动编辑后进入待审核，暂时从公开列表移除，已有报名保留并发送站内消息。修改历史记录关键字段变化；教师设置结束时间及活动取消也写入历史。通知可标记已读；消息不包括邮件、短信或系统推送。活动提醒由服务器约每分钟检查一次；服务器须在提醒窗口内运行，学生登录后可查看，不向浏览器外发送。活动已取消、未获审核或已经开始时不会发送提醒。审核历史从此版本开始记录，不能补出之前没有保存的审核时间与每次意见。二维码使用当前浏览器所访问的服务器地址：127.0.0.1 只能在本机使用，其他设备扫码需要能访问的局域网或部署地址。

## 验证

- Windows、JDK 26，Gradle 离线构建和 17 项自动化测试通过，覆盖会话权限、并发报名、数据重载、旧版数据读取、活动审核与修改、站内消息和社团申请。
- 使用独立数据及本机 Chrome 测试社团提交、教师驳回、站内意见、重新提交与通过、学生报名、活动修改及重新审核通知、管理员名单和分类、社团申请与负责人列表。
- 实际生成海报并验证下载；使用 OpenCV 对浏览器生成的二维码解码，链接与原地址一致。
- 上述验证针对测试场景，未进行完整无障碍审计、性能压测和所有浏览器/设备测试。

## 边界与后续事项

- 兴趣分类为固定选项；审核记录自新版本启用后产生，旧版未保存的信息无法还原。
- JSON 仅支持单个服务进程；站内消息需要登录查看；不能替代正式生产环境的数据库、账号安全与运维。
- `Activity` 和 `State` 新字段带默认值，自动化测试验证了旧结构读取。新数据写入后旧版不保证能读取；升级部署前先备份。测试数据与本地已有 `data/state.json` 分开。
- 后端保持 Kotlin/Ktor；未新增单独 Java 源文件。二维码库为 qrcodejs，许可证位于 `src/main/resources/static/qrcode-LICENSE.txt`。
