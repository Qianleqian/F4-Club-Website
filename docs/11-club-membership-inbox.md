# 社团成员审核与站内收件箱

本次修改保持 Kotlin/Ktor 和本地 JSON 存储；原有 SQLite 演示数据库未接入网站。现有账号、社团和活动继续读取原数据，新字段均有默认值，旧数据不包含成员记录时不会被自动推断为已加入社团。

## 学生注册与加入社团

- 学生注册可选择申请一个已有社团，或选择暂无社团以后再申请。注册成功后账号可登录，但申请社团不等于已获得成员资格。
- 学生首页有“我的社团”和“全部社团”；后者显示未加入、审核中、审核未通过和已加入的状态，可申请加入多个社团。审核未通过后可再次申请。
- 所属社团的负责人在“成员审核”中处理申请，驳回时须填写原因。系统拒绝跨社团审核和无权限操作。
- 审核通过后，在学生收件箱中发送欢迎消息；驳回时发送原因。申请提交后也会通知对应社团的有效负责人。

## 成员限定活动

- 活动创建及编辑表单提供“仅限本社团成员报名”选项。教师审核页、活动卡片和详情页均显示该限制。
- 服务器根据已通过负责人审核的站内成员记录核验；待审核、被驳回或其他社团成员不满足要求。手工填写的其他参加条件仍是说明文字，不能自动验证。
- 没有接入学校统一身份认证；该功能只验证本站的学生角色和负责人审核后的社团成员资格，不能证明校内真实身份。旧活动不会根据自由文本自动推测成员限制，负责人需检查并设置。若活动已有非成员报名，不能直接改成仅限成员，避免使既有报名与规则冲突。

## 收件箱和活动变更

- 所有已登录角色均可查看“站内收件箱”。报名成功向学生发送恭喜消息；报名失败也保留失败通知，包括资格不符、名额已满、报名截止、重复报名等原因。接口仍返回相应错误状态。
- 负责人修改活动开始或结束时间后，已报名学生收到具体变化并看到活动重新送审；取消时收到取消通知。审核结果继续按原流程通知。
- 因成员信息与通知储存在现有 JSON 文件中，服务端更新时必须保留原 `DATA_FILE` 并先备份，不能用演示数据库覆盖。

## 视觉与测试

- 移除首页按钮箭头及首页装饰星形；分享弹窗移除指定提示，并将分享区域和海报背景调整为活动卡片的浅绿色。
- Kotlin/Ktor 测试覆盖旧数据读取、成员申请与负责人审核、跨社团和角色权限、报名资格、报名失败通知、人数已满、截止、时间变更和取消通知。
- 本地浏览器使用隔离数据验证注册选社团、学生独立申请、负责人审核、待审资格拒绝、通过后欢迎和报名、变更与取消通知、移动端布局及海报背景；注册、社团页面、收件箱和审核表单用 axe-core 扫描。自动扫描不等于完整无障碍审查。
