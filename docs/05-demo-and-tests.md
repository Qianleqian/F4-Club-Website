# 演示与测试记录

## 六步演示脚本

1. 启动服务器，匿名浏览已发布示例活动。用 student 登录，在“我的报名”确认初始列表为空。
2. 退出，以 club 登录，创建一场开始时间晚于截止时间的新活动。确认社团列表显示待审核。
3. 退出，以 student 登录，搜索新活动，确认公开列表中不可见。
4. 退出，以 teacher 登录，在待审核列表通过活动；也可另建活动测试驳回理由。
5. 退出，以 student 登录，搜索刚批准的活动，查看详情并报名。再次报名应被拒绝，在我的报名中应有一条记录。
6. 以 club 查看报名名单；以 admin 创建一个测试账号并禁用该账号，确认它不能登录。

扩展示范：社团取消一个已报名活动，学生的我的报名保留历史记录并显示已取消。停止并重启服务，再次登录检查数据仍存在。

## 自动化测试

执行 `.\gradlew.bat test`。以下用例在源代码中提供，执行结果以本地生成的测试报告为准。

| 测试 | 覆盖需求 | 关键断言 |
|---|---|---|
| 提交与审核 | FR-04、05 | 审核前隐藏、学生无权审核、驳回理由必填、通过后可见 |
| 报名与重载 | FR-06、07、08、NFR-03 | 重复拒绝、名单一致、文件重载仍存在 |
| 最后名额并发 | FR-07、NFR-04 | 两个请求争抢一个名额，恰好一个成功 |
| 截止和取消 | FR-07、09 | 截止时拒绝、取消后拒绝及公开列表隐藏 |
| 账号及社团隔离 | FR-08、10、NFR-01 | 非管理员拒绝、跨社团拒绝、禁用失效 |
| 输入与事务 | FR-03、04 | 无效容量、日期被拒绝，文件不留下无效活动 |
| 四角色 HTTP 流程 | FR-01、04、05、06、10 | Cookie、401/403、审核报名、账号停用、数据落盘 |

HTML 测试报告位于 `build/reports/tests/test/index.html`。目前未进行压力测试，也未开展真实用户验收。
