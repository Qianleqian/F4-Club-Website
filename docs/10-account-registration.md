# 账号注册与管理员审核

日期：2026-11-23。对应本地项目的注册功能增量。

## 使用流程

1. 点击右上角“登录”，选择“没有账号？注册”。输入昵称、身份、密码及确认密码。昵称同时用作登录账号；需 2 至 30 个字符并保持唯一，密码为 8 至 128 个字符。
2. Student 注册成功后使用昵称和密码登录。
3. Club holder、Teacher、Admin 注册后需管理员审核；Club holder 需要选择现有社团。审核前账号不能登录，也不能使用该身份的权限。
4. 已有管理员进入“注册审核”，查看申请人、身份、所属社团及时间，选择通过或填写意见后驳回。申请人可用昵称和密码尝试登录，查看待审核或驳回提示；被驳回后可重新注册。
5. 通过后按既有角色工作区展示功能。后台权限仍由现有角色检查执行。

## 接口和数据

- `POST /api/auth/register`：提交昵称、密码、角色及可选的社团。学生直接创建账号，其他身份创建待审申请。
- `GET /api/admin/account-applications`：仅管理员可读取待审申请的公开字段。
- `POST /api/admin/account-applications/{id}/decision`：仅管理员可通过或驳回申请；驳回必须填写意见。
- 账号密码与申请密码只保存哈希值，审核列表不返回密码或哈希。申请记录追加到 JSON 状态，旧数据缺少该字段时使用空列表。
- 因用户名与昵称共用，昵称不能与已有账号或待审申请重复。系统不验证所选择的真实身份，由管理员负责核实申请。

## 验证

- Kotlin/Ktor 测试覆盖四种身份、身份权限、待审阻止登录、昵称冲突、社团验证、驳回及重新申请、持久化、旧数据兼容、审核权限和密码不出现在接口及数据明文中。
- 使用隔离数据和本地 Chrome 验证四个身份注册、管理员审核、审核后对应角色界面，320px 视口及注册弹窗的 axe-core WCAG 自动扫描。
- 本版本没有邮件验证、密码找回和校内统一身份认证。管理员需通过其他可信方式核实身份。上线时应使用 HTTPS；当前 HTTP 部署不能保护网络传输中的账号和密码。
